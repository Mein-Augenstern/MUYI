2026-10 模型生态与选型：没有全能冠军
====

一句话定位：2026-10 的模型市场共识是一句话——**没有全能冠军，只有按任务分工的选型表**。三极格局（GPT-5 系综合、Claude Opus 系深推与编程、GLM-5 领跑开源）加上一个硬约束（**价差可达 30 倍**），把"选型"从口味题变成了成本工程题。本文沉淀一张可复用的选型决策表，以及每个结论背后的评测依据。

1 三极格局速览（2026-10 快照）
------

| 阵营 | 当前旗舰 | 强项（有评测背书） | 成本特征 |
| ---- | ---- | ---- | ---- |
| OpenAI | GPT-5.5 / 5.6 Sol | 综合分析与多步执行（投行内部建模任务 88.5% 领先） | 中档，性价比叙事 |
| Anthropic | Claude Opus 4.7 / 4.8 | 深度推理与结构化（FinanceAgent v1.1 64.4% 居首）、长文与编程 | **输出价与 GPT-5.5 差约 30 倍** |
| 开源（智谱） | **GLM-5** | OpenCompass 79.0 分开源第一；与闭源 SOTA 差距缩到 2.3 分 | 自托管可控，API 高性价比 |

外围：Grok 4 一线边缘竞逐；垂直位（写作向 Claude Fable、推理 Sol）按任务另配。

2 GLM-5：开源侧的量级事实
------

- **总参数 744B、活跃参数 40B**（MoE 架构；上代约 320 亿活跃，翻倍级跃升）；
- 开源意义：闭源领先幅度被压到 **2.3 分**量级——"开源自托管是否够用"从信仰题变成可算的账：数据敏感/高 QPS/私有化合规场景，答案几乎自动得出；
- 工程注意：744B 级 MoE 的自托管门槛不在权重下载，在推理侧（专家并行调度与 KV 缓存规划）——选型别只看榜单分。

3 选型决策表（可抄走用）
------

| 任务形态 | 首选 | 依据 | 成本防线 |
| ---- | ---- | ---- | ---- |
| 代码生成/重构（大仓） | Claude Opus 系 | 编程与结构化长链优势 | 按日预算熔断，别按量裸跑 |
| 多步 agent/复杂分析 | GPT-5.6 Sol | 多步执行评测领先 | 中档价，可做默认主力 |
| 高 QPS 结构化任务（分类/抽取/意图） | GLM-5（API 或自托管） | 开源第一且差距 2.3 分 | 三家里每 token 成本最优档 |
| 长文写作 | Claude 系长文位 | 长文质量口碑 | 批量走低价时段 |
| 数据敏感/私有化 | GLM-5 自托管 | 开源可控 | 算 TCO：GPU 折旧 vs API 账单 |

决策骨架只有两问：**任务的最短板在哪项能力上？调用量的成本曲线斜率多陡？**——前者定候选，后者定部署形态。

4 30 倍价差的工程处理
------

- 百万次/日量级下，Opus 与 GPT-5.5 的月账单差可达数十万美元量级——**贵模型只该出现在价值密度最高的链路节点**（最终裁决/复杂规划），前置路由与粗筛全部下沉到便宜模型；
- 这就是模型路由的经济学本质：级联（便宜先答、不确定升级）+ 按任务类型分流，与后端多级缓存同构；
- 追问链预判："为什么不全用最贵的？"→ 把成本当成第五个非功能需求（与前四个：延迟/准确/安全/合规并列），这个问题就变成了正经的容量规划题。

5 评测数字的正确用法
------

- FinanceAgent 64.4%（Opus）、建模 88.5%（GPT-5.5）、OpenCompass 79.0（GLM-5）——**数字只在同 benchmark 内可比**，跨榜比较是常见翻车点；
- 正确姿势：拿公开榜定候选集（≤3 家），再用**自己的任务分布**跑离线评测集定终选——榜单测的是厂商优化目标，你的评测集测的是你的业务分布。
