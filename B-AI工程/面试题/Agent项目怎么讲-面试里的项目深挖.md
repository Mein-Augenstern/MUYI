Agent项目怎么讲-面试里的项目深挖
====

> 定位：面试题目录的第三篇。[基础篇](LLM应用面试题合集.md)和[进阶篇](智能体工程面试题-上下文与脚手架.md)管"知识点怎么答"，这一篇管"你的项目怎么讲"。依据是四篇公开的一面、二面面经（出处见文末）。它们的共同点是：技术题大多是从项目里长出来的，项目讲不清，后面的题也答不深。
>
> **内容来源与局限**：面经是牛客网上候选人自己发布的记录（顺丰、淘天、字节各一场或两场，2026 年 8 月到 11 月），引号里是原帖的问题。"面试官在确认什么"和准备方法是本文的归纳。样本只有四篇，以校招和实习为主；社招的问法会更偏系统和取舍，但从项目讲起这一点是一样的。

一、四场面经是怎么开始的
------

* **顺丰科技，AI 开发工程师一面**（2026-10-19）：作者的总结是"这场基本全程围绕一个AI应用项目展开，没有手撕算法，也没有问太多传统八股，比较关注技术选型和实际系统流程"。项目深挖十问之后是 RAG 十六问、工程部署十问，三段问的是同一个项目的三个侧面。
* **淘天，AI Agent 一面**（2026-11-12）：25 问里，10 问追一个本体化项目，14 问追一个故障排查 Agent；后 14 问里有一半已经是从项目延伸出去的通用题（从零构建 Agent 需要什么、系统提示怎么组织、记忆的时效性）。
* **字节，后端 Agent 二面**（2026-11-04）：第一问是项目解决什么问题、方案是什么，接着问用什么框架、工作流里的节点做什么、有哪些工具，最后一道手撕题。
* **字节，AI Agent 开发二面**（2026-10-09）：公开的部分是项目深挖五问，从"解决了什么问题"一直问到"重做会怎么改"。

四个共同点：**从项目开始**；**要一个具体场景从头走到尾**；**选型会被问"为什么不是别的"**；**出现的数字会被问怎么来的**。知识题不是不问，而是跟在项目后面问，问的往往是项目里出现过的那一个点。

二、六类追问
------

| 追问 | 面经里的原问 | 面试官在确认什么 |
|---|---|---|
| 走一遍 | "能不能举一个完整的例子，把项目所有核心功能串起来？"；"用一个具体场景讲一下执行过程" | 是不是真的做过。做过的人有具体的例子，没做过的人只有架构图 |
| 为什么选它 | "为什么选择直接根据业务逻辑实现，而不是使用现成的Agent框架？"；"为什么选 Agent 而不是写一堆规则脚本，收益到底在哪？" | 选型是不是自己做的，有没有比较过别的方案 |
| 指标怎么来 | "简历里的故障排查效果指标从哪里来？"；"怎么保证检索召回的准确率？如何验证？" | 数字是不是自己测的，测法站不站得住 |
| 是不是自己做的 | "整个项目的前后端都是自己开发的吗？"；"这是你自主完成的项目吗？" | 哪一部分是你的 |
| 最头疼的坑 | "项目里最让你头疼的一个坑是什么，怎么填上的？" | 有没有处理过出了问题的情况 |
| 重做怎么改 | "如果让你重做一遍，哪块你会直接换方案？" | 有没有回头看过 |

最后一列是本文的归纳。准备的时候，每一类写三句话，写不出来就说明这一块还没想清楚：

1. **走一遍**：挑最完整的一个场景，从用户输入说到最终输出，说清每一步在哪个模块发生、中间产物是什么。
2. **为什么选它**：每个关键选型都准备"还看过什么、为什么没选"。答不出比较过的方案，说明选型可能不是自己做的。
3. **指标怎么来**：每个数字都说得出怎么测的——多少条样本、谁来判断、和什么基线比。说不清来路的数字，不要写在简历上。
4. **是不是自己做的**：照实说分工，然后把自己那一块讲深。把整个项目揽下来，随便一个细节就会露馅。
5. **最头疼的坑**：一个具体的故障，怎么发现的，怎么定位，怎么修的，修完怎么确认不会再犯。
6. **重做怎么改**：说一个真实的改动和理由。答"没什么要改的"，多半会被继续追问。

三、面经里的技术题，库里哪一篇有答案
------

四篇里的技术追问，大部分能在库里找到落点。下面挑的是原帖里一字不改的问题：

| 面经里的问法 | 怎么答 | 深入 |
|---|---|---|
| "System Prompt 应该怎么组织？如果要加入当前时间，可以直接放在第一行吗？" | 不可以。系统提示要写成常量，每次都变的东西放进消息。开头一变，提示词缓存全部失效 | [提示词缓存篇](../上下文工程/提示词缓存-让重复的上下文变便宜.md) |
| "工具返回的信息太长，无法直接放进上下文，有哪些处理办法？上下文压缩怎么做？" | 明细存在窗口外，只带回一句摘要；历史深处的工具原始结果最先清 | [四板斧篇](../上下文工程/Agent上下文工程-注意力预算与四板斧.md) |
| "Agent 请求用户授权，或者向用户追问时，执行流程怎么暂停？用户回复后又怎么继续？" | 推迟而不是挂起进程：本轮以"工具被推迟"结束，待执行的调用留在会话记录里，人答复后恢复会话、重新触发同一个调用 | [人机协同篇](../agent/Agent人机协同-从头部智能体看审批与权限设计.md) |
| "记忆的时效性、衰减和更新怎么处理？" | 易变的信息不进长期记忆；空闲期拿会话日志当依据整理纠错；给记忆留删除出口 | [记忆系统篇](../上下文工程/Agent记忆系统-从会话状态到跨会话记忆.md) |
| "为什么一定要固定拆成三层？为什么不直接使用单 Agent 的 ReAct 主循环？" | 先把单个智能体的进度状态和验证回路做扎实；拆成多层会增加协调开销和 token 消耗 | [多智能体编排篇](../agent/多智能体编排与框架选型.md)、[长任务篇](../脚手架设计/Agent长任务-进度状态与增量交付.md) |
| "为什么不直接把完整文档交给大模型处理，而要额外引入RAG？" | 这一问要两面答。数据小而全、结构化程度高的时候，确实不该用 RAG，直接渲染成清单塞进窗口更准更便宜；知识量大到塞不下、查询是长尾的，才需要检索 | [面试合集 Q9](LLM应用面试题合集.md)、[RAG体系篇](../rag/RAG体系与项目定位.md) |
| "功能测试与实际AI效果评估有什么区别？" | 单测是输入确定、输出确定；agent 的输出是自然语言、路径每次不同、执行还会改环境。所以要评"任务有没有完成"，用判定器，不用字符串比对 | [评测篇](../agent/Agent评测与可观测-guards与成本.md) |
| "工作流如何记录各步骤的执行状态和结果？" | 每一轮的模型输入输出、工具调用和结果、耗时、token 数都结构化落盘，能重放一条完整的决策链 | [评测篇](../agent/Agent评测与可观测-guards与成本.md) |

也有几问，库里现在没有成文的答案，如实列在这里：

* "Planner 和 Executor 的工具集合是什么关系？Planner 如果不知道执行层有哪些工具，怎么制定可执行的计划？"——规划器与执行器怎么分工，全库没有展开；
* "本体化和普通 RAG 有什么区别？"——GraphRAG 篇讲的是社区摘要和双层检索，不是本体化；
* "如果知识库里存在多个版本的数据，如何确定召回范围？"——知识库更新和索引新鲜度，只有零散提及；
* "不同用户或工作空间之间的数据如何隔离？"——身份链篇讲的是工具调用时的身份，检索时的权限过滤没有展开；
* "如果PDF里面有图片或者扫描内容，怎么处理？"——只有"表格不能切"一句。

这些缺口和补写计划记在 `docs/治理/台账-B11-B轨双目标重组.md` 的遗留项里。

四、追问链
------

* 面试为什么从项目讲起？→ 项目是最难背的部分。一个具体场景走一遍，做过没做过立刻分得出来；后面的知识题，也多半是顺着项目里出现过的点往下问；
* 被问"为什么不用 X"，想听什么？→ 听你比较过。说出还看过哪些方案、各自的代价、为什么这个场景下选现在这个；
* 简历上的指标被追问"怎么来的"？→ 三件事说清：多少条样本、谁来判断、和什么基线比。个人项目不是生产系统，就照实说样本怎么造的；
* 项目是团队做的，怎么答"是不是自己做的"？→ 照实说分工，然后把自己那一块讲到底。面试官问这句，多半是想知道接下来该往哪里挖；
* 被问"重做会怎么改"？→ 说一个真实的改动和理由，最好是做过之后才看得出来的那种；
* 技术追问答不上怎么办？→ 回到几条原则去推：窗口是预算，注意力有限；每一轮都在为全部上下文付费；模型的输出是概率性的；模型是不可信组件，边界画在工程层。然后把话题带回你做过的那一块。

面试官视角小结
------

项目深挖这一关，没有题库可背，区分度全在"具体"二字。能挑一个场景从输入走到输出、每一步说得出在哪个模块发生的，是真做过；只能报架构名词的，是看过资料。三句话最见分晓：被问"为什么不用另一个方案"时说得出比较过的东西，被问"指标怎么来"时说得出样本和判定方法，被问"是不是自己做的"时照实说分工。最高分信号是主动讲一个后来改掉的设计——做过项目的人都知道第一版哪里不对，没做过的人会说"没什么要改的"。
