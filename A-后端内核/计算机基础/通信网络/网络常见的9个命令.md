看在前面
====

> * <a href="https://mp.weixin.qq.com/s/C2gQJIgNMhpvwNgfq6969A">网络常见的 9 大命令，非常实用！</a>

定位网络问题的思路，按顺序：

1. 确认连通性（ping）
2. 看本机配置（ipconfig）
3. 查物理/链路层映射（arp）
4. 追踪路径（traceroute/tracert）
5. 查路由表（route）
6. 测域名解析（nslookup）
7. 看 NetBIOS（nbtstat）
8. 看连接与端口（netstat）
9. 管理共享/用户/服务（net）

以下 9 个命令以 Windows 为主，Linux 对应命令一并标注。

1. ping 命令
====

* 作用：向目标发送 ICMP 回显请求（Echo Request）探测**网络连通性**，测试能否到达目标、往返时延和丢包率。
* 原理说明：ping 通 = 网络层可达，但 ping 不通不一定网络不通（对方防火墙可能禁 ICMP）。

```java
ping www.baidu.com          # 连续探测（Linux 默认长ping，Windows 发4个包）
ping -t 192.168.1.1         # Windows：不停 ping，Ctrl+C 停止
ping -n 10 192.168.1.1      # Windows：指定发包数量
ping -c 10 192.168.1.1      # Linux：指定发包数量
ping -l 1500 192.168.1.1    # Windows：指定包大小（测MTU）
```

* 常见结果解读：`Reply from...` 通；`Request timed out` 超时不可达；`Destination host Unreachable` 无到目标的路由。

2. ipconfig 命令（Linux: ifconfig / ip addr）
====

* 作用：查看本机 TCP/IP 配置，包括 IP 地址、子网掩码、默认网关、MAC、DNS、DHCP 租约。

```java
ipconfig                   # 简要信息
ipconfig /all              # 完整信息（含MAC、DNS、DHCP）
ipconfig /release          # 释放 DHCP 租约
ipconfig /renew            # 重新获取 IP
ipconfig /flushdns         # 清除 DNS 解析缓存
ipconfig /displaydns       # 查看 DNS 缓存
```

* 排查场景：IP 是 169.254.x.x 说明 DHCP 没拿到地址；改了 hosts/DNS 后用 `/flushdns` 刷新缓存。

3. arp 命令
====

* 作用：查看/管理 IP 地址与 MAC 地址的映射缓存（ARP 表），定位二层连通、IP 冲突、ARP 欺骗问题。

```java
arp -a                     # 查看所有接口的 ARP 缓存表
arp -a 192.168.1.1         # 查看指定 IP 的映射
arp -d 192.168.1.1         # 删除一条缓存（Linux 需 root）
arp -s 192.168.1.1 00-aa-bb-cc-dd-ee   # 静态绑定
```

* 排查场景：ping 同网段不通时看 arp 表有无对方 MAC；网关 MAC 频繁变化警惕 ARP 欺骗。

4. traceroute 命令（Windows: tracert）
====

* 作用：路由跟踪，显示数据包到达目标经过的每一跳路由器 IP 与时延，定位**断在哪一跳**、哪段网络慢。

```java
tracert www.baidu.com      # Windows
traceroute www.baidu.com   # Linux（需安装 traceroute 包）
tracert -d www.baidu.com   # -d 不做反向域名解析，速度更快
```

* 解读：每一行是一跳；出现 `* * *` 表示该跳不响应 ICMP；在某一跳之后全部超时，故障点通常在该跳附近。

5. route 命令
====

* 作用：查看/操作本机**路由表**，控制数据包的转发路径。

```java
route print                          # 查看路由表
route add 10.0.0.0 mask 255.0.0.0 192.168.1.1     # 添加路由
route add 0.0.0.0 mask 0.0.0.0 192.168.1.1        # 添加默认网关
route delete 10.0.0.0                # 删除路由
route change ...                     # 修改路由
```

* 排查场景：能 ping 通 IP 却按错误网卡出流量、多网卡环境分流，需检查默认路由 `0.0.0.0` 与子网路由。

6. nslookup 命令
====

* 作用：查询 DNS，测试**域名解析**是否正常、指定 DNS 服务器是否可用。

```java
nslookup www.baidu.com               # 用默认 DNS 解析
nslookup www.baidu.com 8.8.8.8       # 指定 DNS 服务器解析
nslookup -type=mx baidu.com          # 查询 MX 记录（还可查 A/CNAME/NS/TXT）
```

* 解读：`Non-existent domain` 表示域名不存在/解析失败；返回地址与预期不符时检查 DNS 配置或 hosts。

7. nbtstat 命令
====

* 作用：显示基于 TCP/IP 的 **NetBIOS** 协议统计与本地/远程计算机的 NetBIOS 名称表、名称缓存（Windows 专属）。

```java
nbtstat -n               # 查看本机注册的 NetBIOS 名称
nbtstat -A 192.168.1.100 # 通过 IP 查对方 NetBIOS 名称表
nbtstat -c               # 查看 NetBIOS 名称缓存
nbtstat -R               # 清除并重载 NetBIOS 名称缓存
```

* 排查场景：局域网内按计算机名访问失败、解析到错误主机时清缓存重查。

8. netstat 命令
====

* 作用：查看**网络连接状态、监听端口、路由表、协议统计**，定位端口占用、连接异常。

```java
netstat -an              # 所有连接+端口，数字形式显示地址（最常用）
netstat -ano             # Windows：额外显示占用端口的进程 PID
netstat -anp | grep 8080 # Linux：定位 8080 端口被哪个进程占用
netstat -rn              # 显示内核路由表
netstat -s               # 各协议统计信息（丢包、重传）
```

* 状态解读：LISTEN 监听中；ESTABLISHED 已建立；TIME_WAIT 主动关闭后的等待；`CLOSE_WAIT` 堆积说明应用未关闭连接（泄漏）。

9. net 命令
====

* 作用：Windows 的网络环境管理命令集，管理**用户、服务、共享、会话**这类对象。

```java
net user                          # 查看用户列表
net share                         # 查看共享资源
net use z: \\192.168.1.10\share   # 映射网络驱动器
net start / net stop 服务名        # 启停服务
net view                          # 查看局域网内共享资源的计算机
net statistics server             # 查看服务器统计
```

* 排查场景：检查可疑共享/会话排查入侵；`net stop/start` 重启 Windows 服务。

小结
====

| 命令 | 定位的问题层 |
| --- | --- |
| ping / tracert | 网络连通性与路径 |
| ipconfig / route / arp | 本机配置、路由、二层映射 |
| nslookup | DNS 解析 |
| netstat / nbtstat / net | 连接端口、NetBIOS、共享与服务管理 |
