看在前面
====

> * <a href="https://www.cnblogs.com/greta/p/5624839.html">如何正确地停止一个线程？</a>

停止一个线程意味着在任务处理完毕之前停掉正在做的操作，也就是放弃当前的操作。停止一个线程可以用```Thread.stop()```方法，但最好不要用它：虽然它确实可以停止一个正在运行的线程，但这个方法是不安全的，而且已被废弃（deprecated）。

在 Java 中有以下 3 种方法可以终止正在运行的线程：

1. 使用退出标志，使线程正常退出，也就是当 run 方法完成后线程终止；

2. 使用 stop 方法强行终止，不推荐——stop 和 suspend、resume 一样都是过期作废的方法；

3. 使用 interrupt 方法中断线程。

一、停止不了的线程
------

interrupt() 的使用效果并不像 for+break 那样马上停止循环。调用 interrupt 只是在当前线程中打了一个停止标志，并不是真的停止线程：

```java
// MyThread.run(): for 循环打印 i=1..500000，无任何中断检查
Thread thread = new MyThread();
thread.start();
Thread.sleep(2000);
thread.interrupt();
```

输出会一路打印到 i=500000，说明线程并未停止。结合 interrupt() 源码注释理解其语义：

* 若线程阻塞在 wait()/join()/sleep() 中，中断状态会被清除，并收到 InterruptedException；

* 若阻塞在 InterruptibleChannel 的 I/O 操作上，channel 会被关闭、中断状态被置位，并收到 ClosedByInterruptException；

* 若阻塞在 Selector 上，中断状态被置位并立即从选择操作返回；

* 其余情况仅仅置位中断状态；中断一个不活跃的线程不会有任何效果。

源码层面，interrupt() 最终都落到 interrupt0() 这个 native 方法置位中断标志（若被中断对象阻塞在可中断通道上，再回调其 interrupt()）。

二、判断线程是否已经中断：interrupted() 与 isInterrupted()
------

Thread 类提供了两种方法：

1. interrupted()：静态方法，测试**当前线程**是否已经中断，内部调用当前线程的 isInterrupted()，**会重置**当前线程的中断状态——连续调用两次时第二次必然返回 false；

2. isInterrupted()：实例方法，测试该方法所属线程对象是否已经中断，**不会重置**中断状态。

看 interrupted() 的经典实验：

```java
Thread.currentThread().interrupt();
System.out.println("stop 1??" + Thread.interrupted());
System.out.println("stop 2??" + Thread.interrupted());
```

运行结果：

```java
stop 1??true
stop 2??false
```

注意两个细节：其一，interrupted() 测试的是**当前线程**——如果对子线程 thread 调用 interrupt() 之后在 main 里执行 thread.interrupted()，得到的仍是 false，因为它测的是从未中断的 main；其二，第二次是 false，因为 interrupted() 会清除中断状态（除非期间再次中断）。换成 isInterrupted() 则两次都输出 true，因为它不清除状态。

三、能停止的线程——异常法
------

有了上面的知识，就可以在线程中用 for 语句判断线程是否是停止状态，是则不再运行后面的代码：

```java
@Override
public void run() {
    for (int i = 0; i < 500000; i++) {
        if (this.isInterrupted()) {
            System.out.println("线程已经终止，for循环不再执行");
            break;
        }
        System.out.println("i = " + (i + 1));
    }
}
```

主线程 2 秒后 interrupt()，输出类似：

```java
...
i=202056
线程已经终止， for循环不再执行
```

但 break 只能跳出循环，for 语句**外面**的语句还是会继续执行。解决办法是在检测到中断时抛出异常，让线程在 catch 中统一收尾：

```java
@Override
public void run() {
    try {
        for (int i = 0; i < 500000; i++) {
            if (this.isInterrupted()) {
                System.out.println("线程已经终止，for循环不再执行");
                throw new InterruptedException();
            }
            System.out.println("i = " + (i + 1));
        }
        System.out.println("这是for循环外面的语句，也会被执行");
    } catch (InterruptedException e) {
        System.out.println("进入MyThread类中的catch了......");
    }
}
```

运行结果：

```java
...
i = 402035
线程已经终止，for循环不再执行
进入MyThread类中的catch了......
java.lang.InterruptedException
```

四、在沉睡中停止
------

如果线程在 sleep() 状态下被停止，会是什么效果？

```java
@Override
public void run() {
    try {
        System.out.println("线程开始。。。");
        Thread.sleep(200000);
        System.out.println("线程结束。");
    } catch (InterruptedException e) {
        System.out.println("在沉睡中被停止, 进入catch，调用isInterrupted()的结果是：" + this.isInterrupted());
    }
}
```

运行结果：

```java
线程开始。。。
在沉睡中被停止, 进入catch， 调用isInterrupted()方法的结果是：false
java.lang.InterruptedException: sleep interrupted
    at java.lang.Thread.sleep(Native Method)
```

在 sleep 状态下停止线程会进入 catch 语句，并且**中断状态被清除**，isInterrupted() 变为 false。

反过来，先 interrupt() 再进入 sleep() 也会立刻抛出 InterruptedException——即使 interrupt 发生在 sleep 之前，标志位已经置上，线程一到 sleep 就立即抛异常进入 catch。

五、小结
------

* stop() 已废弃，会直接解锁并破坏对象状态，不安全；正确的做法是 interrupt() + 轮询/异常法；

* interrupt() 只置位标志，不强制停止，线程应在循环中主动检查 isInterrupted()；

* interrupted() 测当前线程且清除状态，isInterrupted() 测目标线程且不清除；

* sleep()/wait()/join() 中收到 interrupt 会抛 InterruptedException 并清除中断状态。
