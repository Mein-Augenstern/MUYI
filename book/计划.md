# MUYI 开源电子书计划

> 状态：待负责人点头 · 2026-10-18
> 一句话：把 361 篇实文编译成带导航/搜索/目录树的在线书，部署 GitHub Pages，README 挂"在线阅读"入口——招聘方体验从"逛仓库"升级为"翻书"。

## 零、铁律（先定死）

1. **单一事实源**：书源 = 仓库 markdown 原文，不复制、不改动任何一篇。内容更新走现有"一篇一 commit"流程，书自动跟随重建。
2. **不重写内容**：本计划只做导航/渲染/部署层。书的"叙事重构"是另一件事（未来若走出版再说）。
3. 版权口径不变：早期整理篇目保留原文中的来源标注，书与仓库同源同版权状态。

## 一、技术选型

| 项 | 选定 | 理由 |
|---|---|---|
| 站点框架 | **VitePress** | 默认主题即专业（Vue 官方文档同款）；本地搜索零配置；中文圈主流，排障资料多；GitHub Actions 部署链路成熟 |
| 部署 | **MUYI 仓自带 Pages**（github.io/MUYI/） | 内容与书同仓同部署；个人主页 io 仓只挂一条链接，不混工程 |
| 构建 | GitHub Actions（push master 自动重建） | 维护规约"一篇一 commit"天然衔接：写完 push，书即更新 |

备选过 mdBook（朴素但默认观感弱）与 Docsify（运行时渲染、SEO 差），不取。

## 二、信息架构（书感的关键）

**V1：轨道即部（Part），轨道内分组即章（Chapter）**

```
首页（书名/定位/怎么读这本书/数据行）
├── 第一部 A-后端内核        ← 仓库目录直接映射
│   ├── 章：Java（并发/JVM/Spring…）  ← 用轨道内 README 的分组生成
│   ├── 章：框架与中间件
│   └── …
├── 第二部 B-AI工程
├── …（七部）
└── 附录：自测清单（121 题可点击跳答案）
```

**V2 增量（书感的升华，不阻塞 V1 发布）**：
- **两条阅读路线**做"序章"软导航：《面试冲刺线》（P0 题 → 答案链路）与《系统学习线》（由浅入深跨轨道）——复用自测清单与轨道 README 的既有分组，只做编排不写新内容
- 每部封面导语（一段话，取自轨道 README 首段）

## 三、实施分期

### M1 骨架上线（半天~一天，做完即可发布）
1. `book/` 目录建 VitePress 工程（srcDir 指向仓库根的白名单映射，不挪文件）
2. 构建脚本：扫描 7 轨道目录生成 sidebar 配置（中文标题 → 路由）
3. 首页（书名/作者/怎么读/入口按钮）+ 主题微调（克制，无花哨）
4. GitHub Actions：push master → 构建 → 部署 Pages
5. README 顶部挂"📖 在线阅读"入口

### M2 精修（+半天）
- 阅读路线序章（两条线）
- 每部封面导语；移动端排版过一遍
- 附录区（自测清单/cheatsheet 入口）

### M3 滚动（不设终点）
- 访问统计方案评估（不引第三方外链脚本为前提）
- 依据"哪些页被读得最多"反哺内容优先级

## 四、风险与对策（按优先级）

| # | 风险 | 对策 |
|---|---|---|
| 1 | **361 篇全部是中文文件名**：URL 编码后路径极长/部分环境兼容问题 | M1 第一步先做 10 篇中文路径的冒烟验证；不通则构建时生成 ASCII slug（标题拼音/编号）路由映射，原文不动 |
| 2 | 原文内相对链接（.md 互链、images/ 引用）在 VitePress 的转换边缘 case（空格/锚点） | 冒烟覆盖；异常清单式修复（构建期链接改写，不改原文） |
| 3 | 全量构建时长 | VitePress 千页级无压力，预计 <2min；实测确认 |
| 4 | 早期"整理自网络"篇目在书形态下的版权观感 | 保留每篇来源标注不变；书首页版权说明与仓库一致 |
| 5 | 仓库根有非内容文件混入书源 | 白名单制（7 轨道目录 + 自测清单 + 指定附录），其余不进书 |

## 搜索索引评估（2026-10-31，P3 治理批次）

- 实测：394 篇规模下本地搜索索引约 5.5-6MB（单文件 JS，首次搜索前需整包下载）；当前首搜延迟 ~2s 可接受
- **阈值与动作**：约 500 篇/索引 8MB 触发分卷构建（按轨道分册各自带索引，共享一份根导航）；此前先做 M2 既定的“搜索索引预热”（首页空闲时预取索引）
