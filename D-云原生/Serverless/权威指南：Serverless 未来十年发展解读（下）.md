课题三：Serverless 文件系统（CFFS）——状态性优化
====

**现状问题**：当前 Serverless 的状态共享/存储分为两层：

* 计算层：FaaS 提供服务，实例相互隔离，仅有短暂状态性——函数运行完毕即销毁，状态随之消失；

* 存储层：需要持续写入 BaaS（对象存储、KV 存储等）实现长期存储与共享。

**由此带来两大痛点**：

1. 延迟问题——这也是许多 BaaS 服务的通病；

2. 以 API 方式提供的对象/KV 存储，无法感知底层存储情况，开发和迁移时难以信任这些资源，改变了以往的开发使用方式。

**目标**：提供"类似本地磁盘一样的存储能力，区别只是在云端"的文件系统。

**CFFS（Cloud Function File System）特点**：

* 基于标准 POSIX API，提供持久化存储能力——像使用本地文件一样使用云端存储；

* 透明传输机制：函数启动时随之启动一个传输（transaction），函数销毁时传输被提交（commit），从而获取函数执行过程中的状态信息；

* 积极利用本地状态和缓存，相比传统文件存储系统性能更优。

**架构**：CFFS 运行于云服务商的 FaaS 环境中，前端通过标准 POSIX API 调用，后端对接专为 FaaS 设计的存储系统（利用缓存等机制）。

参考：hpts.ws 上 Schleier-Smith 2019 年论文

课题四：Cloudburst——状态敏感、延时敏感场景
====

* 面向社交网络、游戏、机器学习预测等对状态和延迟都敏感的场景；

* 基于 Python 环境，可低延迟地获取共享可变状态；

* 与 CFFS 类似，在函数执行器（executor）中使用数据缓存，但额外保证**因果一致性（causal consistency）**，以获得更好的性能；

* 实验对比：相同条件下，使用 DynamoDB 的 Lambda 函数延迟约 239ms，而 Cloudburst 的延迟低于 10ms，两个数量级的差距；

* 定位：让"状态敏感型"应用也能享受 Serverless 的弹性，而不必迁回传统集群。

参考：github.com/hydro-project/cloudburst 及 arXiv:2001.04592

课题五：Serverless 数据中心（Warehouse-scale Computer）
====

* 传统思路：CPU、内存、GPU、硬盘先组成服务器，再组网形成数据中心；

* 新概念"分布式集群（distributed datacenter）/ Warehouse-scale computer"：将同类型的硬件元素（如 CPU、内存）集中组合，应用需要某种资源（GPU 加速、硬盘、自定义加速器）时才进行分配——即**把一个数据中心看做一台计算机**，提升整体资源利用率；

* 此类硬件开发已在进行中，Serverless 应考虑适配这种集群模式，这也将改变当前面向单机的应用开发模式。

参考：USENIX FAST'14 keynote（Asanović）

对开发者的启示：当"数据中心即计算机"成为现实，应用开发的视角要从"我拿到了哪几台机器"转变为"我需要多少 CPU、多少内存、多少 GPU"，资源以池化方式按需供给——这正是 Serverless 编程模型得以成立的基础。

Serverless 方向预测
====

背景：2009 年 Berkeley 曾预测云计算的发展，部分正确（无限资源池、无前期付费等），但没有预见到云计算的第二阶段——Serverless 阶段。本次对下一个十年的预测如下：

**1. 特定应用场景与通用场景都将成为 Serverless 主流**

* 特定场景：在弹性伸缩平台中实现特定操作（写数据库、实时数据队列、机器学习等），用户代码需遵守平台限制（运行环境、时长、暂无 GPU 加速等），这些限制会随技术成熟逐步放宽；

* 通用 Serverless：FaaS 函数被 BaaS 拓展（如 Starburst、缓存服务），配合对象/文件存储保存长期状态，用户可自定义软件服务（如 SQL 能力），支持流数据处理、机器学习等——凡能运行在服务器上的场景都可归入此类。

**2. 成本具备竞争力**

Serverless 自带高可靠与弹性扩缩容，计费更精确、资源利用率逐步提升，真正做到按需使用付费，将比预留资源更便宜。对比：预留实例在低峰期为峰值买单，利用率常低于两成；Serverless 按毫秒计费，空闲时成本为零，对流量潮汐明显的业务（营销活动、定时批处理）尤其划算。

**3. 机器学习场景持续优化**

云服务商将提供工作流调度、环境配置（如预置内存）等能力，同时这些优化也会反哺通用场景的平台性能。

**4. 硬件多样化**

摆脱对 X86 架构的强依赖，引入新硬件架构（ARM、RISC-V、各类加速器），由用户/云厂商选择最合适的硬件，实现更高的利用率与性能。对机器学习等专用负载，硬件选型的自由度将直接转化为性价比优势。

**补充观察**：这两个阶段的预测有一个共同的逻辑——计算与存储持续解耦、资源持续池化、抽象层级持续上移。开发者每上移一层，就不必再关心一整类运维问题（机器、集群，再到容量）。

总结
====

* Serverless 是云计算的下一个阶段，三大核心特征：隐藏服务器复杂概念、按需付费、弹性伸缩；

* 实现上由 FaaS 与 BaaS 共同组成；最直观的转变类比：**从租车到打车**；

* 学术研究方向包括：效率提升（性能、可用性）、具体应用抽象（机器学习、数据处理）、通用层面抽象；

* Serverless 可能改变我们对"计算机"的看法——摆脱本机硬件限制，从云端获取无限资源、随取随用。
