## 三、保障机制

* **`scripts/check_links.py`**：区分大小写的链接体检。`--src` 查仓库源文（死链、大小写、裸空格、未收录）；`--dist` 查构建产物（死链、死图）。
* **`scripts/stats.py`**：篇数、题数、配图数等的唯一来源。`--json` 供在线书构建时读取，`--check` 校验 README 里的数字。
* **部署脚本带三道门禁**：仓库链接与导航收录 → README 数字 → 构建产物链接。任何一道不过就中止，不发布。
* **每周体检流水线修复**：constellation 改为克隆到工作区之外；并入上面两道本库门禁。

## 四、导航

**规则**（`book/.vitepress/build-sidebar.mjs`）：

1. 轨道按字母序，默认折叠，只自动展开读者当前所在的轨道；
2. 每个目录的第一项是它的导读页，标签统一为「<目录名> · 导读」——原先直接取页面 H1，全库有四种叫法。标签带上目录名是为了页面底部的「上一篇 / 下一篇」：那里用的是同一个标签，只写"目录导读"就不知道是哪儿的导读；
3. 其余条目按 README 里出现的先后排。**README 的目录顺序就是书里侧边栏和「上一篇 / 下一篇」的顺序**，README 没提到的排在后面。

**构建期改写**（`book/scripts/prepare-src.mjs`，只动构建副本）：目录链接在有导读页时保留可点、没有时降为纯文本（原先不分情况一律降级，导读页的章节表因此在书里整张点不动）；`xxx/README.md` 改写成目录地址；指向不进书内容的链接改指 GitHub；README 末尾的「写作规范」段在书里去掉；空 README 与配图目录说明不再挂成空白页。

## 五、阅读体验

* **首页**：数字全部来自构建时生成的 `stats.json`，不再手抄（原先硬编码在四处，且全都不准）；终端里演示的命令与输出换成仓库里真实存在的；轨道卡片按字母序；手机端标题在前、终端在后。
* **图表按需加载**：去掉 `vitepress-plugin-mermaid`（它把整套图表库静态打进主包），改为 markdown 输出 `<pre class="mermaid">`、主题在页面上真的有图时才加载图表库。首页首屏 JS/CSS：47 个资源 / 压缩后 704KB → 10 个 / 93KB。
* **手机表格**：单元格保底约 5 个汉字宽，列多的表横向滚动。

## 六、自动化

* **push 即部署**：新增 `.github/workflows/deploy-site.yml`，push 到 master 自动过门禁、构建、发布到 Cloudflare Pages。删除已停用且目标站已下线的旧 GitHub Pages 部署工作流。
* **凭据**：CI 使用新建的最小权限 token（仅 Pages Write，ID `935cc1a106654faeb0e6027100912218`，2027-11-24 到期），只存于 GitHub Secrets（`CF_PAGES_DEPLOY_TOKEN`、`CF_ACCOUNT_ID`），本地不留副本。本机钥匙串里的 token 是智能体用的账户级 token（170 多个写权限组），没有进 CI。

## 七、口径变更

* **篇数改为只数正文**（396），不含 README 与配图说明。原口径含 README（482），但根 README 轨道表一直用的是一套对不上任何口径的旧数。详见《协作与统计口径约定》第一节。
* **轨道顺序统一为字母序**：原根 README 轨道表为 A C G B E F D，侧边栏与首页为 A B C G D E F。

## 八、更正（评审过程中报错的数字）

* "57 篇未被导航页收录"有误，实为 **26 篇**。当时的统计脚本没处理 `%20` 编码与路径里的空格。
* "Kubernetes / Docker 目录的 README 是冒名的配图说明"有误：那两个目录下是**小写** `readme.md`，是 10 月治理时的刻意设计（小写不进书）。被 macOS 不区分大小写的文件系统误导。因此这两个目录不单独建导读页，改由 `D/容器技术/README.md` 覆盖。

## 九、遗留（未在本批处理）

1. **页内 H1 与文件名不一致的老文章**：B7 只规范了文件名。侧边栏标签取的是 H1，所以个别条目仍显示博客原标题（如 `MySQL基础-架构与SQL执行流程.md` 的 H1 仍是"敖丙系列--《我们一起进大厂》系列…"）。建议下一批次规范页内标题；数量未精确统计。
2. **13 篇老文章用 "Question" 作英文小节标题**，夹在中文标题之间。
3. **内容错误 1 处**：《强引用、软引用、弱引用、虚引用》把 `FinalReference` 写成强引用；它是供 finalize 机制用的内部引用类。
4. 各目录 README 表格里的子目录篇数是手写的，新增文章后需同步（轨道级篇数与根 README 已由 `stats.py --check` 把关，子目录级没有）。
5. 原有七维体检的观察项：巨无霸（>15000 字）17 篇；互链孤岛 16 篇。
6. GitHub Dependabot 提示 book/ 依赖有 10 个已知漏洞。

## 十、执行过程中自己引入并修掉的问题（自查记录）

* **首次自动部署失败**：部署脚本用相对路径调用时（CI 里是 `./scripts/deploy-cloudflare.sh`），`cd` 进 `book/` 之后就拿相对路径去找仓库根下的脚本，找不到。门禁在发布前把它拦住了，线上没有受影响。修法是先解析成绝对路径；另加 `DEPLOY_DRY_RUN=1` 演练模式，并在本机按 CI 的调用方式完整演练。
* **本机构建与 CI 产物不一致**（macOS 文件系统不区分大小写所致，最终靠比对 CI 日志发现）：
  * `existsSync("README.md")` 在本机能匹配到小写的 `readme.md`，于是把 9 个配图说明里的 2 个（Docker / Kubernetes）挂成了导读页——CI 里没有这两个页面。评审时说的"Kubernetes 目录的 README 是冒名的配图说明"，其实就是这个本机构建假象。现改为逐级核对真实文件名。
  * `rglob("README.md")` 在本机把小写的一并数进来，导读页数出 95，实际 84。`stats.py` 已改为精确计数。
  * 修第一处时又引入一个 bug（路径带结尾斜杠时判断失败，导致 4 个无导读页的目录链接没被降级），被本地的产物体检拦下，未进入 CI。
