# MUYI 内容治理计划（电子书精修）

> 状态：执行中 · 2026-10-18 启动 · 预计 20+ 小时，跨多轮会话
> 性质：精细活，一步一步来。每个动作一篇一 commit，全程可回溯可反悔。

## 一、治理目标

知识库框架（7 轨道）、电子书（VitePress）已就绪，本任务治理**内容本身**：
让每一篇都配得上"一本电子书"的标准——没有搬运冗余、没有碎片散落、命名成书。

## 二、判定标准（先定规则，再动手）

### 删除（严标准，宁少勿多）
- 纯搬运：全文转载且无个人增量（有来源标注、无"回填/反哺/复盘"标记）
- 严重过时：技术版本已淘汰且无面试考察价值
- 空价值：标题党/清单罗列且信息量趋零
- 每次删除在台账留记录（文件名、原因、字数），git 历史可恢复

### 合并
- 同主题碎片：2~3 篇讲同一件事 → 并 1 篇（保留最全的为底，吸收其余增量）
- "补充-xxx""xxx(二)"类续篇附件 → 并入主篇对应章节
- 合并后原文件删除，主篇头部注明"合并自：xxx/yyy（2026-10）"

### 改名（电子书化命名）
- 目标句式：`主题：副标题` 或完整陈述句（对标 README 精选：
  "分布式ID：从雪花算法到生产实现"、"支付回调的HMAC验签与幂等设计"）
- 清除："(开发者必看)""了解一下""补充-"等口语尾巴；文件名内多余空格/括号
- **改名联动铁律**：改名前 grep 全库引用（互链+自测清单 121 题定位），
  改名后同步改引用，跑书构建验证零死链后才提交

### 不动
- 2026 生产反哺的深度文（内容标尺，只做命名微调）
- 每篇的来源标注（版权口径）
- 7 轨道目录结构（只动叶子，不动骨架）

## 三、工作流（每个批次固定五步）

1. **盘点**：脚本统计目录内每篇——字数/标题/来源标注/含"生产反哺"标记/最后修改时间
2. **打标**：台账中逐篇标注动作（保留/改名/合并→目标/删除）与理由
3. **执行**：一篇一 commit（`治理: <动作> <文件>`），改动即提交
4. **联动**：改名/删除的引用同步（互链、自测清单）
5. **验证**：书全量构建零死链 + 台账勾选完成
