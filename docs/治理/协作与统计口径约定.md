# 协作与统计口径约定

> 2026-10-31 定稿（P0 治理批次）。本文解决两个反复出问题的口径：**README 统计数字怎么算**、
> **多会话/多人并行写库怎么不打架**。所有数字规则都可用脚本复算，不依赖人肉记忆。

## 一、统计口径（README 数据行与轨道表的唯一依据）

| 指标 | 定义 | 复算命令 |
|---|---|---|
| 篇数（各轨/总数） | kb-upkeep audit [6] 的各轨 md 计数（含轨道 README 与 picture 说明 readme；排除 book/.git/.mimosa/node_modules） | `bash <constellation 的 audit.sh> <库根>` 看 [6] 段 |
| 自测题数 | 自测清单.md 中表格数据行数 | `grep -c '^\| [0-9]' 自测清单.md` |
| 配图数 | git 跟踪的图片文件总数（png/jpg/jpeg/gif/webp，排除 book/） | `git ls-files \| grep -iE '\.(png\|jpe?g\|gif\|webp)$' \| wc -l` |

**更新纪律**：任何批次增删文章/题目/图片后，按上表复算并同步 README 数据行与轨道表——数字永远可被任何人用命令重现。历史口径变更：2026-10-31 前数据行曾用人工策展数（347），与脚本口径（394）出现 47 篇偏差，自本文起统一为脚本口径。

## 二、多会话并行写库纪律（防裹挟与覆盖）

背景：多 Agent 会话并行建设本库（曾发生 `git add -A` 把另一会话未提交改动裹挟进提交的事故）。

1. **提交用显式文件名**：`git add <path1> <path2>`，禁止 `git add -A / git add .`；
2. **写前探测**：动手前 `git status --short` 看是否有他人未提交改动，有则只动自己的文件并在回报中说明；
3. **不改别人口径**：README 统计行只按第一节规则整体更新，不混入私人口径；
4. **推送失败降级**：github.com 主站阻断时走 git data API 通道（constellation/skills/github-cn），远端 tip 实时获取不依赖本地指针；
5. **批次台账**：跨文件治理动作（改名/去重/迁移）一律落 `docs/治理/台账-B*.md`，先记后做或同步记录。

## 三、引用规范

见根 README「引用与诚信规范」条目：研读重写 + 文末标注来源/版权；原文勘误或占位如实注明，不做虚假归属。先例：javadoop 系列 37 篇（台账 B8）。
