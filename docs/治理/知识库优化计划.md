### 1.2 结构问题

- **双轨重叠**：contents/（速查）与 java/interview/（深度）同主题两套并行（Java-basic vs java基础、JVM.md vs JVM/），互相不联动，更新极易漂移。
- **无导航**：README 仅 3 行；258 篇内容无索引入口，检索全靠翻目录。
- **docs/ 平铺混杂**：架构/方法论/专业术语/加解密平级摆放，与 java/interview 无引用关系。
- **问题清单.md 是孤儿**：纯问题列表，无答案链接，不能自测。
- **碎提交**：git log 大量"Update 同文件×4"式提交，历史不可读。

### 1.3 时效断层（2024 → 2026）

虚拟线程、JDK 17/21 LTS、Spring Boot 3（Jakarta/AOT/Native Image）、ZGC 生产化、MySQL 8、K8s 普及、**LLM 应用工程**——全部零覆盖。而后两者正是当前求职市场与个人方向的重叠区。

## 四、内容补全（第二阶段，按优先级）

### P0 — 面试权重最高 × 完全缺失（第 1-3 周）

| 主题 | 篇目规划 | 素材来源 |
|---|---|---|
| **Redis 全套** | 数据结构与底层编码 / 持久化 RDB+AOF / 过期与淘汰 / 高可用（主从哨兵集群）/ 缓存穿透击穿雪崩 / 分布式锁（SETNX→Redlock→Redisson）/ 与 MySQL 一致性 | 通用资料 + star-site 若引入则实战反哺 |
| **消息队列** | Kafka 架构与高性能原理 / 可靠投递（ACK/重平衡/幂等）/ 顺序消息 / 事务消息 / RocketMQ 对比选型 | star-site star-async 组件可反哺异步可靠性一篇 |
| **系统设计场景题** | 秒杀 / 短链系统 / Feed 流 / 限流四种算法与工程选型 | 整合现架构/高并发 3 篇为母版 |

### P1 — 时效升级（第 4-6 周，随查随更）

- 虚拟线程 vs 线程池（JDK21）：结构对比、适用场景、与 synchronized pinning 问题
- JDK 17/21 语言新特性：record / sealed / 模式匹配 / 文本块——迁移注意点
- Spring Boot 3：Jakarta 迁移、AOT、GraalVM Native Image
- GC 现代化：ZGC/Shenandoah 原理与调优（补进现 JVM 板块，标注 JDK 版本差异）
- MySQL 8 新特性（CTE/窗口函数/原子 DDL/隐藏索引）

### P2 — 架构与云原生补全（穿插）

- K8s 体系：核心对象（Pod/Deployment/Service/Ingress）/ Operator 思想 / 排障实战
- 观测性三件套：Metrics（Prometheus）/ Logging（Loki）/ Tracing（OpenTelemetry）+ Arthas 实战
- 组件层分布式：一致性哈希工程实现 / 分布式 ID。**star-site 的 SequenceWorkerIdAllocator + 雪花算法生产实现直接反哺**——库里已有理论篇，缺生产篇。

### P3 — AI 应用工程（B 轨，与项目实战滚动同步）

- LLM 基础：Transformer 直觉 / token 与上下文窗口 / 温度与解码 / 幻觉成因与缓解
- RAG 体系：文档切分策略 / 嵌入模型选型 / 向量库（Milvus/pgvector）/ 检索重排 / 评测
- Agent 工程：ReAct 模式 / 工具调用设计 / LangGraph 状态机 / 记忆系统（**ai-service 的 ReAct + ContextVar 身份注入 + SSE 流式可直接成文**）
- Prompt Engineering：吴恩达课程要点落地（已有链接清单，缺笔记本体）
- LLM 应用面试题：上下文工程 / 多轮会话状态 / 安全（提示注入）——2025-2026 大厂 AI 岗高频

### D 轨 — 算法（长期，低强度）

不追求刷全。目标：**LeetCode Hot100 高频 50 题**，每题一篇（思路→复杂度→坑点），按题型分组。每周 3 题节奏，一年内完成。

## 五、维护机制

1. **实战反哺钩子**：star-site/voice-zcode 每完成一个技术组件，当天回写一篇到对应主题。已可反哺清单：雪花 ID、HMAC 回调验签、SSE 流式、LangGraph Agent、Mimosa 安全门禁、Docker 编排。
2. **季度自测**：每季度末过一遍《自测清单.md》的 P0 部分，标记掌握度。模糊项安排重读。
3. **提交纪律**：一篇一 commit，消息规范见上文；禁止碎片式 Update 连击。
4. **年度体检**：每年 10 月跑一次本盘点脚本（主题覆盖 + 关键词时效）。决定来年补全重点。
