金融信贷域 · 架构方案
====

> 本层回答：**这个业务域需要哪些系统、系统间怎么分工与演进**。粒度介于"业务知识"（业务怎么运转）与"系统设计"（单个系统怎么实现）之间。

## 与其他层的关系

- 上承 [业务知识/](../业务知识/)：每个架构决策必须能追溯到业务动因（额度模型决定账务系统形态）
- 下启 [系统设计/](../系统设计/)：架构方案定义系统边界，系统设计填充边界内部
- 横向参照 C-架构/系统设计/（平台无关的方法论场景）——业务耦合方案放本域，平台无关场景放 C 轨，**通过互链挂钩而非复制**
